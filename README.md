# Бот авторизации

Для локального запуска нужны JDK 25, работающий бэкенд Training Collector и собственный Telegram-бот от @BotFather. Скопируйте `.env.example` в `.env` и укажите:

- `AUTH_BOT_TOKEN` — токен этого Telegram-бота.
- `PLATFORM_URL` — адрес платформы, локально `http://127.0.0.1:8080`.
- `AUTH_SERVICE_KEY` — ключ, настроенный под этим же именем на платформе.

Запуск — `./gradlew run`, сборка — `./gradlew build`. Gradle читает локальный `.env` для запуска. Переменные процесса имеют приоритет. В продакшене передайте переменные контейнеру и используйте HTTPS или закрытую сеть для доступа к платформе.

```sh
docker build -t training-collector-auth-bot .
docker run --env-file .env training-collector-auth-bot
```

В контейнере задайте `PLATFORM_URL` с доступным из контейнера хостом. Бот работает в режиме long polling, достаточно одного запущенного экземпляра на Telegram-токен.

При регистрации тренер открывает персональную ссылку с сайта. Бот привязывает Telegram и присылает два сообщения — заголовок и код для входа.

Сквозной тест регистрации и выдачи кода находится в проекте `integration` бэкенда. Команда запуска приведена в его README.

## Vercel

Импортируйте репозиторий отдельным проектом. В Production задайте `PLATFORM_URL` (постоянный HTTPS-адрес бэкенда), `AUTH_SERVICE_KEY` и `AUTH_BOT_TOKEN`. При первом запуске бэкенд должен отвечать на `/health`.

Vercel запускает Dockerfile как Daemon `auth-bot` в Production. В конфигурации указан один экземпляр в `iad1`. При выборе другого региона перенесите туда единственный экземпляр. Для локальных проверок используйте отдельный Telegram-токен. После запуска зарегистрируйтесь на сайте и проверьте доставку заголовка и шестизначного кода в личный чат.
