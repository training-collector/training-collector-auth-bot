# Бот авторизации

Для локального запуска нужны JDK 25, работающий бэкенд Training Collector и собственный Telegram-бот от @BotFather. Скопируйте `.env.example` в `.env` и укажите:

- `AUTH_BOT_TOKEN` — токен этого Telegram-бота.
- `PLATFORM_URL` — адрес платформы, локально `http://127.0.0.1:8080`.
- `AUTH_SERVICE_KEY` — ключ, настроенный под этим же именем на платформе.

Запуск — `./gradlew run`, сборка — `./gradlew build`. Gradle читает локальный `.env` для запуска. Переменные процесса имеют приоритет. Все настройки и их значения по умолчанию перечислены в `src/main/resources/auth-bot.conf`.

```sh
docker build -t training-collector-auth-bot .
docker run --env-file .env -e PLATFORM_ALLOW_INSECURE=true training-collector-auth-bot
```

В контейнере задайте `PLATFORM_URL` с доступным из контейнера хостом. Адрес платформы должен начинаться с `https://`. Адрес `http://` принимается только для локального хоста или с флагом `PLATFORM_ALLOW_INSECURE=true` в закрытой сети. При локальном запуске бот получает обновления через long polling и раз в секунду проверяет очередь доставки. Достаточно одного запущенного экземпляра на Telegram-токен.

При регистрации тренер открывает персональную ссылку с сайта. Бот привязывает Telegram и сообщает об ожидании администратора. После одобрения бот сообщает, что аккаунт активирован. Тренер входит на сайте по Username, и бот присылает запрос входа с кнопками **Разрешить вход** и **Отклонить вход**. В сообщении указано число, которое показывает сайт, а также браузер и IP-адрес запроса. Кабинет открывается в той вкладке, которая запросила вход. После нажатия кнопки исчезают, а вместо них появляется итог. Ответить может только привязанный аккаунт Telegram.

Сквозной тест регистрации и подтверждения входа находится в проекте `integration` бэкенда. Команда запуска приведена в его README.

## Развёртывание

Сервис разворачивается целиком на одном сервере, вместе с ботами, сайтами и PostgreSQL. Конфигурация и инструкция находятся в `training-collector-deploy`. Бот получает обновления Telegram через long polling: публичный адрес, вебхук и секрет ему не нужны. Раз в секунду он проверяет очередь запросов входа и уведомлений (`AUTH_POLL_INTERVAL`). На один токен должен работать один экземпляр.
